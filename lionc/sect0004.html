3 Czytanie programów „C”.

Nauka czytania programów napisanych w języku „C” jest jedną z przeszkód, które należy pokonać, zanim będzie można efektywnie studiować kod źródłowy UNIX-a.

Podobnie jak w przypadku języków naturalnych, czytanie jest umiejętnością łatwiejszą do opanowania niż pisanie. Mimo to musisz zachować ostrożność, aby nie przeoczyć niektórych bardziej subtelnych punktów.

Istnieją dwa „Dokumenty UNIX”, które odnoszą się bezpośrednio do języka „C”:

„Podręcznik referencyjny C” autorstwa Dennisa Ritchiego

„Programowanie w C – samouczek” autorstwa Briana Kernighana

Powinieneś przeczytać je teraz, o ile możesz, i od czasu do czasu wracać do nich, aby przeczytać je ponownie, z coraz większym zrozumieniem.

Nauka pisania programów w języku „C” nie jest wymagana. Jeśli jednak masz taką możliwość, powinieneś spróbować napisać przynajmniej kilka małych programów. Reprezentuje to akceptowany sposób nauki języka programowania i zrozumienie prawidłowego korzystania z takich elementów, jak:

średniki;
„=” i „==”
"{" I "}"
„\(++\)” i „\(--\)”
deklaracje;
rejestruj zmienne;
Stwierdzenia „jeśli” i „za”.

Przekonasz się, że „C” jest bardzo wygodnym językiem umożliwiającym dostęp do struktur danych i ciągów znaków oraz manipulowanie nimi, na czym polega duża część systemów operacyjnych. Jak przystało na język terminalowy, który wymaga zwięzłego, zwięzłego wyrażenia, „C” używa dużego zestawu znaków i sprawia, że ​​wiele symboli, takich jak „*” i „&”, ciężko pracuje. Pod tym względem zachęca do porównania z APL.

Istnieje wiele cech języka „C”, które przypominają PL/1, ale znacznie wykracza poza ten ostatni w zakresie udogodnień przewidzianych dla programowania strukturalnego.

3.1 Niektóre wybrane przykłady

Poniższe przykłady pochodzą bezpośrednio z kodu źródłowego.

3.2 Przykład 1

Najprostsza możliwa procedura, która nic nie robi, występuje dwukrotnie(!) w kodzie źródłowym jako „nullsys” (2864) i „nulldev” (6577), sic.


  6577 nulldev ()
       {
       }

Chociaż nie ma żadnych parametrów, nawiasy „(” i „)” są nadal wymagane. Nawiasy „{” i „}” wyznaczają treść procedury, która jest pusta.

3.3 Przykład 2

Następny przykład jest nieco mniej trywialny:

  6566 nodev ()
       {
        u.u_error = ENODEV;
       }

Dodatkowa instrukcja jest instrukcją przypisania. Jest zakończony średnikiem, który jest częścią instrukcji, a nie separatorem instrukcji, jak w językach podobnych do Algolu.

„ENODEV” to zdefiniowany symbol, tj. symbol, który przed faktyczną kompilacją jest zastępowany przez preprocesor kompilatora powiązanym ciągiem znaków. „ENODEV” jest zdefiniowany w linii 0484 jako 19. Konwencja UNIX jest taka, że ​​zdefiniowane symbole są pisane wielkimi literami, a wszystkie inne symbole małymi literami.

„=” jest operatorem przypisania, a „u.u_error” jest elementem struktury „u”. (Patrz linia 0419.) Zwróć uwagę na użycie „.” jako operator wybierający element konstrukcji. Nazwą elementu jest „u_error”, co można przyjąć za paradygmat sposobu konstruowania nazw elementów konstrukcji w kodzie źródłowym UNIX: po literze wyróżniającej następuje podkreślenie, po którym następuje nazwa.

3.4 Przykład 3

  6585 bcopy (from, to, count)
       int *from, *to;
       {
        register *a, *b, c;
        a = from;
        b = to;
        c = count;
        do
          *b++ = *a++;
        while (--cc);
       }

Funkcja tej procedury jest bardzo prosta: kopiuje określoną liczbę słów z jednego zestawu kolejnych lokalizacji do innego zestawu.

Istnieją trzy parametry. Druga linia

   int *from, *to;

określa, że ​​pierwsze dwie zmienne są wskaźnikami do liczb całkowitych. Ponieważ dla trzeciego parametru nie podano specyfikacji, domyślnie przyjmuje się, że jest to liczba całkowita.

Trzy zmienne lokalne, a, b i c, zostały przypisane do rejestrów, ponieważ rejestry są łatwiej dostępne, a kod obiektowy służący do odwoływania się do nich jest krótszy. „a” i „b” są wskaźnikami do liczb całkowitych, a „c” jest liczbą całkowitą. Deklarację rejestru można było napisać bardziej pedantycznie, np

   register int *a, *b, c;

aby podkreślić związek z liczbami całkowitymi.

Należy dokładnie przestudiować trzy linijki zaczynające się od „do”. Jeśli „b” jest typem „wskaźnika do liczby całkowitej”, to

    *b

oznacza wskazywaną liczbę całkowitą. Zatem, aby skopiować wartość wskazywaną przez „a” do lokalizacji oznaczonej przez „b”, moglibyśmy napisać

    *b = *a;

Gdybyśmy zamiast tego napisali

    b = a;

spowodowałoby to, że wartość „b” byłaby taka sama jak wartość „a”, tj. „b” i „a” wskazywałyby to samo miejsce. Przynajmniej tutaj nie jest to wymagane.

Po skopiowaniu pierwszego słowa ze źródła do miejsca docelowego należy zwiększyć wartości „b” i „a” tak, aby wskazywały kolejne słowa z odpowiednich zestawów. Można to zrobić pisząc

    b = b+1; a = a+1;

ale „C” zapewnia krótszą notację (która jest bardziej użyteczna, gdy nazwy zmiennych są dłuższe), a mianowicie.

    b++; a++;

Teraz nie ma różnicy pomiędzy stwierdzeniami „b++;” i „++b;” Tutaj.

Jednakże „b++” i „++b” mogą być użyte jako terminy w wyrażeniu i w takim przypadku są one różne. W obu przypadkach efekt zwiększania „b” zostaje zachowany, ale wartość wprowadzana do wyrażenia jest wartością początkową dla „b++” i wartością końcową dla „++b”.

Operator „\(--\)” podlega tym samym zasadom, co operator „++”, z tą różnicą, że zmniejsza się o jeden. Zatem „\(--\)c” wprowadza wyrażenie jako wartość po pomniejszeniu.

Operatory „++” i „\(--\)” są bardzo przydatne i są używane w całym systemie UNIX. Czasami będziesz musiał wrócić do pierwszych zasad, aby dokładnie ustalić, co implikuje ich użycie. Należy również pamiętać, że istnieje różnica pomiędzy*b++I(*b)++.

Operatory te mają zastosowanie do wskaźników do struktur, a także do prostych typów danych. Kiedy zwiększany jest wskaźnik zadeklarowany w odniesieniu do określonego typu struktury, rzeczywista wartość wskaźnika jest zwiększana o rozmiar struktury.

Teraz możemy zobaczyć znaczenie tej linii

    *b++ = *a++;

Słowo jest kopiowane, a wskaźniki zwiększane – wszystko za jednym razem.

Linia

    while (--c);

wyznacza koniec zestawu instrukcji, który rozpoczął się po „do”. Obliczane i testowane jest wyrażenie w nawiasach „\(--\)c” (testowana wartość jest wartością po pomniejszeniu). Jeśli wartość jest różna od zera, pętla jest powtarzana, w przeciwnym razie zostaje zakończona.

Oczywiście, jeśli początkowa wartość „count” byłaby ujemna, pętla nie zakończyłaby się prawidłowo. Gdyby taka możliwość była poważna, należałoby zmodyfikować procedurę.

3.5 Przykład 4

  6619 getf (f)
       {
         register *fp, rf;
         rf = f;
         if (rf < 0 || rf >= NOFILE)
           goto bad;
         fp = u.u_ofile[rf];
         if (fp != NULL)
         return (fp);
       bad:
         u.u_error = EBADF;
         return (NULL);
       }

Parametr „f” jest przypuszczalnie liczbą całkowitą i jest kopiowany bezpośrednio do zmiennej rejestru „rf”. (Ten wzór stanie się tak znajomy, że przestaniemy już o nim wspominać.)

Trzy proste wyrażenia relacyjne

  rf < 0    rf >=NOFILE    fp != NULL

każdemu z nich przypisuje się wartość jeden, jeśli jest prawdziwa, i wartość zero, jeśli jest fałszywa. Pierwszy sprawdza, czy wartość „rf” jest mniejsza od zera, drugi, czy „rf” jest większy od wartości zdefiniowanej przez „NOFILE”, a trzeci, czy wartość „fp” nie jest równa „NULL” (która jest zdefiniowana jako zero).

Warunki sprawdzane za pomocą instrukcji „if” to wyrażenia arytmetyczne zawarte w nawiasach.

Jeśli wyrażenie jest większe od zera, test kończy się pomyślnie i wykonywana jest poniższa instrukcja. Zatem jeśli na przykład „fp” miało wartość 001375, to

    fp != NULL

jest prawdą i jako terminowi w wyrażeniu arytmetycznym przypisuje się mu wartość jeden. Wartość ta jest większa od zera i stąd stwierdzenie

    return(fp);

zostanie wykonany, aby zakończyć dalsze wykonywanie „getf” i zwrócić wartość „fp” do procedury wywołującej jako wynik „getf”.

Wyrażenie

    rf < 0 || rf >= NOFILE

jest logiczną alternatywą („lub”) dwóch prostych wyrażeń relacyjnych.

Zanotowany zostanie przykład instrukcji „goto” i powiązanej etykiety.

„fp” ma przypisaną wartość, którą jestadres, z „rf” -tego elementu tablicy liczb całkowitych „u_ofile”, który jest osadzony w strukturze „u”.

Procedura „getf” zwraca wartość do procedury wywołującej. Jest to wartość „fp” (tj. adres) lub „NULL”.

3.6 Przykład 5

  2113 wakeup (chan)
       {
         register struct proc *p;
         register c, i;
         c= chan;
         p= &proc[0];
         i= NPROC;
         do {
             if (p->p_wchan == c) {
               setrun(p);
             }
             p++;
         } while (--i);
       }

Istnieje wiele podobieństw między tym przykładem a poprzednim. Mamy jednak nową koncepcję, szereg struktur. Aby wprowadzić trochę zamieszania, w tym przykładzie okazuje się, że zarówno tablica, jak i struktura nazywane są „proc” (tak, „C” na to pozwala). Są one zadeklarowane na arkuszu 03 w następującej formie:

  0358 struct proc
       {
         char p_stat;
         ..........
         int p_wchan;
         ..........
       } proc[NPROC];

„p” jest zmienną rejestru typu wskaźnik do struktury typu „proc”.

    p = &proc[0];

przypisuje „p” adres pierwszego elementu tablicy „proc”. Operator „&” w tym kontekście oznacza „adres”.

Zauważ, że jeśli tablica ma n elementów, elementy te mają indeksy dolne 0, 1, .., (n-1). Dopuszczalne jest również napisanie powyższego stwierdzenia prościej jako

    p = proc;
